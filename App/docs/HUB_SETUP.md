# Hub chapters (Path of Radiance)

Open **Chapters → Create hub**. Choose a free chapter number, title, template chapter, dedicated avatar and the chapter after which the hub opens. The map is either a copy of the template's map or a new flat grass map of the chosen width and height. The template's units, events and messages are not copied: the avatar is the only unit. The avatar must not be deployed in another chapter.

The hub is then an ordinary chapter: every chapter tab works on it (Build with zoom, render, terrain, props and units, Map settings, Script, Dialogue…). On its **Build** tab the toolbar has one more tool, **Hub** (◎). In it, add a linked chapter, then click the map to place its action tile and its return point (drag either one later to move it). Each link offers **Arrive**, which enters the chapter. An optional short description adds **Visit** on the same tile; Visit shows the message and leaves the avatar in the hub. The avatar starts on its unit's tile: move it with the Select tool. Other armies may hold decoration units; the player army must stay the avatar alone. Links are kept in `hub_draft.json` until **Install hub**, which needs at least one link. Run it again after changing them. **Chapters → Edit hub** opens the hub chapter's Build tab. Use chapter 29 for activation after the two-part chapter 28–29.

The setup appends persistent campaign flags and generated events, then installs routing in `main.dol`. The first victory of the activation chapter stores its normal successor and opens the hub. Clearing a selected chapter returns to the hub while `HUB_ACTIVE` is set. Clearing the saved next story chapter advances the saved story position. Chapter 28 and 29 remain one continuous segment. If installation fails, the draft stays for a later retry.

To leave hub mode, put `clr("HUB_ACTIVE")` in the selected chapter's story event before its victory. That victory loads the saved next story chapter. If it *is* the saved next story chapter, it loads that chapter's normal successor. To start another hub period later, a story event can set `HUB_ACTIVE` again; the already-saved story position remains available only until it is resumed.

Hub visits are omitted from the game's forty-entry chapter-clear history. The generated hub script clears the avatar's acted flag after each action and updates the map, allowing repeated moves and actions within the player phase. **Wait also counts as an action**, so the avatar can cross any distance by moving, waiting, and moving again. The game's effective Movement maximum is **20**; larger class-record values are clamped at runtime. Set Movement only as high as the distance wanted for one leg. Do not add Canto or an infinite-action skill: Canto preserves only unused movement, while the generated refresh already grants another full action. Test this behavior in Dolphin with the specific actions your hub offers, especially any custom action or scripted movement.

Changing the names or order of the generated `HUB_*` global flags changes how saves interpret their bits. Keep their registration slots fixed after distributing saves.
