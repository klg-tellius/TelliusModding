# Formats and tools

Read this file only for work involving game-file parsing, serialization, media conversion, disc tooling, or format test coverage. For reverse-engineering work or new format discoveries, also follow `research.md`.

## Format layer

`fe_modding/formats/` contains independent readers and writers used by the GUI:

- Container and compression: `lz10.py`, `pak.py`, and `common.py`.
- Text and scripts: `message.py` (also `engine_name_hash`, the game's message-ID hash key), `fe9_message_scene.py` (lossless step view of an FE9 message for the scene editor: `decompile`/`compile_steps`, step catalog, templates, and the Font menu's `apply_font`/`strip_fonts`), `event_script.py` (read-only view used by the conversation preview) and the `cmb/` package for event scripts:
  - `cmb/model.py` + `cmb/binary.py`: a symbolic model (branches to labels, strings by text) and a full reader/writer. `write_cmb(read_cmb(x)) == x` for every vanilla script; functions and instructions can be added or removed.
  - `cmb/parser.py`, `cmb/compiler.py`, `cmb/decompiler.py`: the `.fe9s` language ([Script language](script-language.md)). The decompiler verifies each function by recompiling it (structured → goto → `asm:` fallback), so `compile(decompile(x))` reproduces `x`. Every function of the 43 vanilla scripts comes out in the structured form (no `goto`, no `asm:`).
  - `cmb/catalog.py` + `externs_fe9.json`: trigger kinds and the 406 natives + 89 `startup.cmb` helpers with argument counts and inferred argument kinds, regenerated by `python -m fe_modding.formats.cmb.build_catalog <research/main_dol/fe9_script_externs.tsv> <Scripts dir>`.
  - `cmb/source_tools.py`: text edits the editor performs (function spans, decorators, new/duplicate/delete).
  - `cmb/script_zones.py`: the map zones of a chapter script (`@on_area`/`@on_location` functions) for the Build tab: list, add (new function or an untriggered one), move/edit, and delete (an empty function is removed, another is kept untriggered and marked `UNUSED`).
  - `event_flags.py`: the script flag table and its place in a save. Slot prediction from source (`global_flags`, `local_flags`, `slot_names`, `capacity_problem`), the engine hash (`flag_hash`), and `.gci` save blocks (`save_blocks`, `read_flag_bits`, `write_flag_bits`, `refresh_crc`). The compiler uses it to warn about `set`/`get`/`clr` on unregistered names, `global()` outside `RegistGlobalFlags`, duplicate registrations and a full table; the script editor passes the project's own `startup.cmb` globals. `python -m fe_modding.formats.event_flags save.gci --scripts <Scripts dir> [--set F ...] [--clr F ...]` lists or edits a save's flags. Source edits for the Flags page: `registration_sites`, `append_registration` (after the last registration, so no slot moves), `rename_registration`, `flag_uses`, `check_flag_name`, `exported_functions`. The compiler also warns when an edit of `RegistGlobalFlags` moves a vanilla campaign flag to another slot.
  - `script_sources.py` (package root): loading and saving a script as source the way the Script tab does (`load`, `peek` without side effects, `save`, the `script_sources/` sidecar), `shared_scripts`/`chapter_script`/`startup_path`, and `CompileContext` - the project `startup.cmb`'s campaign flags and exported helpers, passed to every compile.
- Chapter data: `dispo.py` and `map_file.py`.
  - `dispo.parse_dispo` / `build_dispo` turn a `dispos_*.bin` into a `DispoDocument` (sections of 48-value units whose pointer fields hold label strings) and back, rebuilding the label pool, relocation table and header counts; every vanilla file round-trips byte for byte. `add_unit`, `remove_unit`, `move_unit` (spawn and destination together), `find_counterpart_unit` (the same unit in another difficulty file) and `dispo.FIELD` (field index by name: `level`, `faction`, `bonus_hp`…) work on it. `insert_unit` and `patch_unit_field` remain for raw values.
  - `map_props.move_instance` / `rotate_instance` / `tile_heights`; `map_scene.topdown_camera` / `render_topdown` draw the map from straight above aligned to the tile grid (GPU or CPU renderer).
- Textures and UI metadata: `tpl.py` and `rect.py`. `tpl.replace_region` replaces one rectangle of one image (an icon of an icon sheet, `gui/icon_viewer.py`): pixels outside it decode unchanged; a C8/C4 image with its own RGB5A3 palette gets the new colours in palette entries no outside pixel needs (duplicate entries merged first), other formats re-encode and copy back only the blocks touching the rectangle.
- Audio and video: `dsp_adpcm.py`, `stm.py`, `thp.py`, and `gcfesnd.py` (the `Sound/gcfesnd.bin` BGM cue catalog - read support for all 116 real `BGM_*`/`FF_*` records, plus a narrow `repoint_bgm_cue()` write op that repurposes one of the retail game's own unused cue slots for a new track, rather than growing the record array).
- Fonts: `fe9_font.py` reads GCF fonts (`GameFont`: glyph lookup as the game does it, masks, sheets, `bitmaps()`) and writes them (`build_gcf` shelf-packs glyph bitmaps tallest first on I4 sheets of the original size; `rebuild` rewrites a font with added or replaced glyphs, and every vanilla font rebuilds glyph-for-glyph at the same size). `import_truetype` renders a TrueType/OpenType file with Pillow's FreeType into an existing font's metrics (`ImportOptions`: size or auto, character list, additions, offsets, spacing, antialiasing); coverage comes from `fontTools` when installed, else from what FreeType draws. `FONT_FILES` maps font index to file. `gui/font_viewer.py` is Assets › Fonts. Tests: `tests/test_fe9_font.py`.
- Icons and weapon models: `icons.py` maps an item's `icon` to cell `96 + icon` of `window/icon.tpl` image 0 (24×24) and a skill's icon byte to cell `n − 1` of image 1 (32×32), and finds an item's battle model the way the game does (`weapon_tables` reads `zdbx.cmp`'s `xwp/<NAME>.dbx`, `weapon_model` follows its `Model` block to `<folder>/<model>.cmp`; `forged_model_path`: `xwp/forge/<name>_b.cmp`). `model_viewer` lists `xwp/` sets and refuses a static import on composite (bow) weapons (`is_skinned_weapon`). Tests: `tests/test_icons.py`.
- Global tables: `fe8data.py`, `shop.py`, `anim_registry.py`, and `effect_registry.py`. `anim_registry.build_anim_registry` writes `FE8Anim.bin` (byte-identical for vanilla records); `fe8data.add_label` appends a label to `FE8Data.bin`'s string pool so a record can point at a new name. `patch_character_field`, `patch_class_field`, `patch_item_field` and `patch_skill_field` write every decoded field of their record (IDs are unique and added to the pool; name, description, model and effect keys are added when new; fields naming another record must name an existing label; `weapon_ranks` strings are added when new, so records sharing the old string keep it). `patch_skill_field("sid")` also renames the record's `SID_` symbol; `restricted_to` and `skill_items` rewrite the label lists (in place when they fit and are not shared, else appended). `patch_record_bytes` overwrites a whole character, class, item, skill or chapter record but refuses to change a pointer word (`protected_record_words`: the kind's pointer fields plus every word of the record on the pointer list). Tables are found through their symbols (`table_start`, `table_count`), never at fixed offsets. `read_table`/`write_table` rebuild a table as `RawRecord`s (bytes plus the words on the pointer list); `add_record` (empty or a copy, with a new ID), `remove_record` and `move_record` use them. A table that grows moves to the end of the data section with room for eight more records (`replace_section`, shared with `supports.py`; the old place is zeroed and a later growth reuses the room). `FIXED_TABLES` (skills) refuse a count change; `SAVED_BY_NUMBER` lists the tables saves hold by position. The smaller sections have writers too: `patch_game_data`, `write_group_names`, `write_battle_skies`, `write_battle_terrain`, `patch_chapter_field`, `patch_terrain_names` and `patch_database_head`. Labels are found by `_label_offset`: a string an existing pointer already names, else one inside the string pool (never inside a table), and Shift-JIS labels are supported. `fe_modding/fe8_references.py` lists what names a record (`record_references`: pointer fields of `FE8Data.bin` described by record and field, support lists and bonds by owner, and the scripts, deployments, shops, `zdbx.cmp`, `FE8Anim.bin` and `main.dol` that contain the ID); `gui/record_actions.py` is the New/Remove flow the editors share. `shop.parse_shop`/`build_shop` read and write a Path of Radiance `shopitem_<n|h|m>.bin` as a document of label strings (byte-identical for the vanilla files): armory/vendor lists, the 45-cell forge grid (`forge_cells`, `set_forge_item`) and `add_chapter` for a chapter number without shops.
- 3D data: `skeleton.py`, `model.py`, `gs_file.py`, `animation.py`, `engine_pose.py`, `gltf_export.py`, and `gltf_import.py`. `model.py` decodes a `.gs` mesh into render-ready data; `gs_file.py` is its lossless container layer (`read_gs`/`write_gs`). `skeleton.write_skeleton_file` and `animation.write_animation` are the `.g`/`.ga` writers. All three writers rebuild every file on the Path of Radiance disc byte-for-byte (1,785 `.gs`, 1,785 `.g`, 4,422 `.ga`). `skeleton.bind_world_matrices` chains the bones' `+0xBC` matrices the engine's way.
  - `engine_pose` ports the engine's animation evaluation: curves overwrite slots of each bone's value block, `local_matrix` builds the Maya-style bone matrix, and `pose()` returns world matrices and the skinning palette (`world × skin_matrix`) for any frame. The 3D Models viewer poses meshes with it.
  - `gltf_export.export_glb` writes a `.glb` (mesh, skeleton, textures, animations). Joints sit at each bone's rotate pivot and their inverse bind matrices are `T(-pivot)·skin_matrix`, so glTF skinning reproduces the engine's palette. Animations are sampled per game frame with `engine_pose`, with the event track and loop settings in each animation's `extras`. Triangles use glTF winding, and material colors include the engine's ×1.25.
  - `gltf_import.import_static_model` turns a `.glb`/`.gltf` into a **static** `.gs` plus a `.tpl` (`tpl.build_tpl`) for its textures: node transforms baked, vertices moved into one bone's bind space, quantized to the game's fixed point, stripified, one shape per material, cull mode from glTF `doubleSided`. The material's `alphaMode` picks the draw list: `OPAQUE` list 0, `MASK` list 1 (alpha-tested cut-outs), `BLEND` list 2 (blended); skinned imports do the same, and `gltf_export` writes `alphaMode` from each material's list. `gltf_import.texture_for_tpl` picks CMPR for images whose alpha is only 0 or 255 (`tpl.encode_cmpr` writes CMPR's transparent 3-colour blocks for RGBA input) and RGB5A3 otherwise. Multi-texture materials and per-shape blend flags are not imported.
  - `gltf_import.import_skinned_model` builds a skinned `.gs` for an existing skeleton. Joints match bones by name and vertices stay in the skin's bind space. Vertices with one bone go into multi-matrix shapes of at most 10 bones. Vertices blending several bones go into composite shapes, which the engine skins on the CPU with up to four bones per vertex. Their fixed-point range is sized from the class animations (`engine_pose.posed_extent`); `smooth=False` keeps each vertex on its heaviest bone.
  - `gltf_import.import_animation` turns one glTF animation into a `.ga` for an existing skeleton: joints are posed each frame, converted to the engine's bone values (scale, XYZ Euler rotation, translation) and reduced to the keys linear interpolation needs. Events come from the glTF `extras` or from the animation being replaced.
  - `gs_stats.model_stats` gives a `.gs` file's size and precision figures (visible triangles, vertices, blended vertices, shapes by skinning type, bones, fraction-bit steps and ranges). `MAP_BODY_LIMITS` (`ymu/`) and `BATTLE_BODY_LIMITS` (`zu/`) hold the largest vanilla figures that the import review compares against.
  - `model.TriChunk.hidden` marks shapes with flag `0x400`, which the game never draws; the viewer, `gltf_export` and `gs_stats` skip them.
  - `gltf_import.build_skinned_gs(composite_only=True)` puts every triangle in composite shapes, as vanilla battle models are built; `model_viewer.replace_battle_body_with_glb` uses it for `zu/` models and writes the mesh into every weapon pack (uncompressed `.pak`).
  - `gltf_import.build_skeleton` builds a new `.g` from the glTF armature (joints at their bind positions, the vanilla character-rig convention) and `check_rig_against` lists anchor bones (`_s1_`, `_sw1_`...) the new armature lacks or moved.
  - In-game results are listed in `research/MODEL_IMPORT_PLAN.md` ("In-game results").
- Battle engine text tables: `zdbx.py` reads and rebuilds `zdbx.cmp` (`build_zdbx_archive`, byte-identical for vanilla) and edits its tables: `set_job_model` (job-list lines by animation ID, class, or class plus character), `clone_model_dbx`/`clone_param_dbx`, `param_textures`/`set_param_texture`.
- Map terrain: `model_viewer.export_map_terrain_glb` and `replace_map_terrain_with_glb` (static build via `gltf_import.build_static_gs` with `tex_id_base` and a trailing white texture record; images added with `tpl.append_images`, which keeps every existing image's bytes and index); `fe_modding/map_heights.follow_terrain` moves `map.bin`'s ground and combined elevations and the prop heights by the surface change; `fe_modding/terrain_conform.conform_to_tiles` cuts and flattens the playable area onto the tile panels; `tpl.truncate_images` drops trailing images without re-encoding the rest. `map_file` reads panel elevations as signed and panel indices as 0-based, and writes resized sections (`replace_section`, `write_panel_layer`, byte-identical for unchanged layers of every map) and instance heights (`patch_build_inst_height`).
- Animated props: `map_props.import_prop` (skinned glTF → skeleton, mesh, `.ga`, `FLAG_C_ANIMATED`; `loop`), `export_prop_glb` (with skeleton and animation).
- Terrain texturing: `model_viewer.replace_map_terrain_with_glb(map_texturing, mask, keep_light)`, `terrain_mask_image`, `MAP_MASK_SPAN`; `gltf_import.UV2_MATERIALS` / `ATTR_TEX1` (second UV set written for `map_base`/`map_wall`), `gltf_export` writes `TEXCOORD_1`; `terrain_conform` interpolates both UV sets.
- Water flow: `map_props.water_scroll` / `set_water_scroll` (footer slot 3 of the water `.ga`).
- Map water: `map_props.import_water` (replace or add, from a donor map), `water_names`, `water_terrain_mismatch`, `MAP_FLAG_WATER`; `map_file.patch_extra_field(..., "unknown_tail", ...)` writes the map flags; `map_props.read_map_container` unpacks a `map.cmp`. Prop and water imports reuse a `texpack.tpl` image identical to an imported one.
- Rig contract: `rig_contract` (anchor purposes, `COMBAT_CODES`, `event_errors`, `replace_events`, `weapon_bones` / `visibility_warnings` for map weapons, `read_battle_roles` from `zu/<code>.dbx`, the rig kit sheet); `model_viewer.export_rig_kit`, `kit_animation_names`, `replace_animation_events`, `_fallback_animation` (new-rig fill-in).
- New rigs from any humanoid: `rig_fit` (`read_rig`, `body_chains`, `game_ends`, `auto_mapping`, `fit_rig`); `model_viewer.rig_kit_glb`, `prepare_rig_fit`, `fit_new_rig` (`max_triangles` reduces the fitted mesh).
- Mesh reduction: `mesh_reduce.simplify` does quadric-error half-edge collapses on positions and triangles, with optional skin weights and locked vertices. `glb_triangle_count` counts a glTF's triangles, and `reduce_glb` returns a reduced `.glb` with everything else kept. In `model_viewer`: `map_triangle_budget`, `map_locked_joints` (the set's weapon bones), `reduce_map_glb`, `reduction_note`.
- Battle rigs: `model_viewer.replace_battle_rig_with_glb(new_rig=None)`, `gltf_import.build_skeleton(template=...)` (battle bone conventions), `animation.retarget_animation` (by bone name), `model_viewer.battle_weapon_bones` / `vertices_on_bones` (weapon-in-body warning).
- Map texture pack: `map_props.compact_texpack` (drop unused `texpack.tpl` images, renumber every `.gs`), on top of `tpl.select_images` (keep chosen images, blocks copied unchanged) and `gs_file.remap_texture_ids` (in-place `tex_id` patch).
- Tile heights: `map_heights.tile_corners` / `set_tile_corners` (per tile and layer, `LAYERS`; a changed tile gets its own panel record and keeps its terrain pointer, through `map_file.write_panel_layer`) and `deduce_corners` (ground from the terrain and low non-raising props, combined and roof flat at the highest covering prop's base plus `prop_rise`). `fe_modding/prop_heights.RISE` is the per-object rise measured on every vanilla map (the most common value over the tiles each object covers alone). The chapter map's data lives in `gui/map_editor.MapEditor` (no tab of its own); the Build tab's windows are `gui/map_windows.py`.
- Map props across maps: `map_props.prop_catalog` / `map_props_info` (every map's props as `PropInfo`, cached per `map.cmp` until it changes), `copy_prop` (model, skeleton, animation and `mapbuilddesc` record from another map; images copied byte for byte with `tpl.copy_images`, or shared when `tpl.image_keys` finds the same image already there; texture ids renumbered with `gs_file.remap_texture_ids`), `same_prop`, `free_prop_name`. `gui/prop_browser.py` is the browser shared by the Game Data Map Objects tab and the Build tab's picker; `MapEditor.edit_pack` applies a whole-pack edit, and the Build tab's undo snapshots the whole pack.
- Map props: `fe_modding/map_props.py` (`export_prop_glb`, `import_prop`, `place_prop`, `remove_instance`), on top of `map_file.add_build_object`, `instance_record` (footprint rule for quarter turns), `set_build_instances` and `instance_records`.
- Class movement type and stats: `ClassEntry.movement_type` / `base_stats` (`0x44`) / `growths` (`0x54`), `fe8data.MOVEMENT_TYPE_NAMES`, `patch_class_field` (`movement_type`, `base_statN`, `growthN`). Terrain stats: `fe8data.patch_terrain_stats` (shared or own block), `terrain_block_users`, `terrain_stats_block`.
- Terrain types: `fe8data.read_terrain_types` (77 `TerrainData` records with their stats blocks), `fe8data.read_message_texts` (`mess/common.m` by Shift-JIS key), `map_file.terrain_grid` / `set_tile_terrains` / `add_pool_string`.
- Supports: `formats/supports.py` reads and writes `RelianceData` (`read_support_lists`, `write_support_lists`, pair helpers `set_pair`/`remove_pair` that edit both characters' lists, reuse empty slots and empty instead of delete; `validate_support_lists` refuses one-sided pairs, falling thresholds and more than 10 slots), `KiznaData` bonds (`read_bonds`/`write_bonds`), the `DivineData` affinity table (`read_affinities`, `patch_affinity_bonus`) and a character's affinity pointer at `+0x14` (`character_affinity`, `patch_character_affinity`). A rebuilt section is written in place when it fits, otherwise appended to the data section with its symbol repointed; the old section's pointer-list entries are dropped. Vanilla round-trips byte for byte. `gui/support_editor.py` (`SupportEditorPanel`) edits all of it, one character at a time, plus the support conversations of `Mess/yell.m` (through an embedded `DialogueEditor`); it is the Game Data page's **Supports** tab (route `("data", "supports")`), editing the shared `Fe8DataSession`. `CharacterEntry.fixed_growth_start` (`+0x49`) is the fixed-growth ("Fraction" mode) start accumulator, not support data (`research/SUPPORT_NOTES.md` §8).
- New model slots: `fe_modding/model_slots.py` copies a battle model (`clone_battle_model`, `assign_battle_model`, `set_battle_texture`) or a map model (`clone_map_model`, `assign_map_model`), edits the tables (`job_list`, `remove_job_line`, `remove_battle_texture`, `set_map_textures`) and removes copies (`remove_battle_model`, `remove_map_model`; vanilla models refuse, checked against the kept originals), over `zdbx.job_list_lines`, `release_job_lines` and `remove_param_texture`. `fe8data` pointer writes keep the file's pointer list in step (a null field is unlisted). It registers the copy (see `research/GRAPHICS_NOTES.md`, "Model selection and new model slots").
- 3D preview rendering: `gui/gpu_renderer.GpuSceneRenderer` draws the 3D Models / Maps previews with wgpu (Vulkan, DX12 or Metal, offscreen, read back into one Tk image). Geometry and textures are uploaded once per model and grouped into batches by blend mode and texture layers; posed animation frames only rewrite positions (`update_positions`). The shader follows `model_viewer._sample_texture_layers` and `_ModelCanvas._rasterize` (flat face brightness, stored-normal backface rule, nearest sampling with GX wrap modes, opaque / translucent / additive passes). Without wgpu or a GPU adapter, `_ModelCanvas` uses the numpy rasterizer; `tests/test_gpu_renderer.py` compares the two. Loading is kept short the same way: `tpl` decodes whole blocks with numpy, `model_viewer._load_textures` caches decoded packs by their bytes (a chapter's props share one `texpack.tpl`), each `_LoadedTexture.array` is shared by every triangle using it, and the flat fallback colours come from `_sample_texture_area_batch`. A chapter scene loads in about a second.

Write support exists only where the corresponding module and GUI feature explicitly provide it. Several registry or survey modules remain read-only.

## External tools

`fe_modding/tools.py` is the boundary between the Python application and bundled executables:

- WIT in `tools/wit/` extracts disc images and rebuilds Radiant Dawn. Path of Radiance is rebuilt by `formats/gcdisc.py` (GameCube FST + CISO writer), since WIT turns any extracted folder into a Wii disc.
- FFmpeg in `tools/ffmpeg/` decodes general source video for THP import.

Their provenance and licenses are recorded in each tool directory's `ORIGIN.txt` and license files. The bundled binaries currently support Windows only.

## Verification

Automated tests are in `App/tests/`. They cover project behavior and the format operations represented by synthetic fixtures. Some parsers, especially read-only or less mature formats, have only been checked against extracted Path of Radiance data. Radiant Dawn compatibility must not be assumed for a format unless it has been verified.

`DiscModelRoundTripTests` rebuilds every `.gs`/`.g`/`.ga` on the disc (including inside `pack` archives) and requires byte-identical output. It is skipped unless `FE9_EXTRACTED_FILES` points at an extracted `files/` directory:

```bash
FE9_EXTRACTED_FILES="G:/FE9Mod/My Fire Emblem Mod/extracted/files" python -m unittest tests.test_formats.DiscModelRoundTripTests
```

`tests.test_fe9_message_scene` checks every step kind, and with `FE9_EXTRACTED` set, that every vanilla message survives `compile_steps(decompile(x))` byte for byte with no Raw steps and that each step's regenerated form equals its source.

`tests.test_cmb.VanillaCorpusTests` does the same for event scripts: every `Scripts/*.cmb` must survive `write(read(x))` and `compile(decompile(x))` byte-for-byte. The rest of `tests/test_cmb.py` checks the compiler's output instruction by instruction, its diagnostics, and the editor's source edits.

```bash
FE9_EXTRACTED_FILES="G:/FE9Mod/My Fire Emblem Mod/extracted/files" python -m unittest tests.test_cmb
```
