# Workspace and features

Read this file only for work involving the GUI, navigation, an editor/viewer, or chapter-level behavior.

## Workspace

`fe_modding/gui/app.py` shows the launcher (new project, open folder, recent projects), then the project workspace (`gui/shell.py`). There is no permanent sidebar:

- **Top bar** — the seven sections (Home, Chapters, Characters, Game Data, Flags, Assets, Disc & Patch), **Search everything… Ctrl+K** and the ⚙ **Settings** button (also **Settings ▸ Preferences…** in the menu bar), whose only setting so far is the light/dark theme (remembered in `~/.tellius_modding/settings.json`).
- **Breadcrumbs** under it (Chapters › Ch.3: Pirates Aground › Deployment) with back/forward (**Alt+←/→**).
- **Status bar** — the editors holding unsaved edits, and the count of changes this session; clicking it opens the change log. The log records saves and imports made during the session; it is not persisted with the project.

Pages:

- **Home** — the ways in (a tile per section), "Jump back in" (recent chapter and character pages), and this session's changes. Before extraction only Home and Disc & Patch are available, and Home shows only the Disc & Patch tile.
- **Disc & Patch** — source disc (choose, extract, re-extract with a warning), **Build disc**, **Create patch…** and **Apply patch…** (see [Project lifecycle](project-lifecycle.md#patches)). **File ▸ Apply patch to a disc…** opens the same apply dialog without a project.
- **Chapters** — a card per chapter with the game's own title (`MCTnn` in `system.cmp`), message and unit counts and extra map phases. **Add chapter…** is the last card.
- **Chapter page** — title, disc number and files, previous/next, and a **Phase** selector when the chapter has several map folders (`bmap06`, `bmap06_2`…); the phase drives the Build and Battle scenes tabs. Tabs: **Overview** (the cast of the chosen deployment file grouped by section, each unit opening its character page; the messages grouped by ID prefix, each opening the Dialogue tab on it; the named or triggered script functions, each opening the Script tab on it), **Build** (map and deployment), **Dialogue**, **Script**, **Shops**, **Battle scenes**.
- **Characters** — a portrait card per character, filtered as Playable, Named NPCs & bosses, Generic or All (search covers every category). Story copies sharing a name key (`PID_BOLE_MAP1`) are grouped under the main record. Path of Radiance only.
- **Character page** — portrait, name, class → promoted class (links to Game Data), and the copies of the record. Tabs: **Stats** (the FE8Data record: identity with the name key (`MPID`), skills, personal weapon ranks, map animation IDs, level/build/weight, transform gauge, roster order, biorhythm pattern and phase, personal bonus and growth next to the class's values, the fixed-growth start accumulators, and the whole record as hex; **New character…** adds a record, empty or a copy of one, and **Remove** drops this one), **Supports** (the character's affinity (applied on choice), support partners (slot, partner, partner's affinity, C/B/A thresholds, the bonus at A, and which of the C/B/A conversations exist) and bonds. Selecting a partner edits the pair's thresholds (written to both characters' lists) and removes it; **Add partner** adds a pair (thresholds 1/3/5 to start). The **Conversation C/B/A** buttons open that support conversation (`MYELL_<A>_<B>_<rank>` in `Mess/yell.m`, names without `PID_` in alphabetical order) in Game Data › Supports › Conversations, or create it from the background-scene template with the two faces. A bond's effect and value apply when changed; **Add bond with** adds one. Double-clicking a partner or bond opens the other character's Supports tab; problems in this character's pairs (one-sided, falling thresholds) are listed at the bottom), **Portrait & models** (face file, and the battle and map models the game resolves for the character, unpromoted and promoted, each opening 3D Models), **Appearances** (every deployment record and every chapter message that loads the portrait or names the character; double-click opens it), **Script references** (functions pushing the `PID_`/`MPID_`).
- **Game Data** — tabs for classes, items, skills, terrain types, chapters, the general tables, **Supports** and **Map Objects**. Each record tab shows its records as tiles, like the Characters page: a search box keeps the tiles matching every typed word (Enter opens the first), and a tile shows the record's picture when it has one — the item or skill icon from `window/icon.tpl` (classes have no icon, so their tiles are text only). Clicking a tile opens the record's form, which fills the page under a bar with **‹ All …** (back to the tiles), ◀ ▶ (step through the tiles shown) and the record's position. Every field applies as soon as it is left (Tab, Enter, a click elsewhere, a drop-down choice); an invalid value is reported next to **Save FE8Data.bin** and not written. **Discard unsaved edits** reloads the file for every view of it (character pages included). Supports edit the same shared `FE8Data.bin` as the rest of the page; see [Formats and tools](formats-and-tools.md).
- **Flags** — the 96 script flags (`formats/event_flags.py`), in three tabs. **Campaign flags**: the engine's eight `gf_*` flags and `startup.cmb`'s `RegistGlobalFlags` list, each with its slot and meaning; **Add campaign flag…** appends one, **Rename reserved slot…** renames one of the three unused `G_リザーブド` entries, and a line gives the busiest chapter's remaining room (scanned in the background). **Chapter flags**: a chapter's registrations from `Startup` with their slots, the function registering each and every function that sets, clears or tests it (or uses it as a talk/battle/base-conversation label); **Add chapter flag…** appends one after the last registration. Both rewrite the script at once (compiled onto the current `.cmb`, source kept in `script_sources/`), refuse names that are taken or not Shift-JIS, and leave alone a file with unsaved edits in the Script tab. **Save file**: opens a `.gci`, lists a save block's 96 flags by name (chapter flags named from the script of the block's map) and switches one per double-click or Space; **Save** / **Save as…** write it with the block's checksum recomputed.
- **Assets** — a tile per resource type, each opening its viewer full-page.

The character page and Game Data edit one shared copy of `FE8Data.bin` (`gui/fe8_session.py`), so neither overwrites the other; saving from either writes it once.

Editors are created when first opened and stay alive for the project session, so moving between pages never loses edits. Opening another chapter asks before discarding that chapter's unsaved edits; closing the project, and building, list the editors with unsaved edits.

## Chapters

`fe_modding/chapters.py` discovers chapter resources and groups dialogue, deployment, script, and map data under one chapter selection. Its IDs are disc file numbers: the Prologue is `01`, so these numbers do not match the chapter numbers displayed to players; the pages show the game's titles instead. `chapter_phases()` lists a chapter's map folders.

The app can duplicate a chapter's resource set. Duplication does not add the executable logic needed to make that chapter reachable during normal game progression.

## Chapter tools

- **Dialogue** — edits chapter messages and shows a playable in-app preview of the selected message. The message is chosen in the **Message ID** box at the top (type an ID or part of it and press Enter, or open the list, which shows each ID with the start of its text); **New…**, **Duplicate**, **Rename…** and **Delete** beside it manage messages, and new ones can start from a template. For Path of Radiance the left column lists the message's steps in its top half, with a **Step** tab (the selected step's fields) and a **Raw text** tab below; the right column shows the stage on top and the preview in the rest. Both edit the same bytes. The preview decodes background changes, portrait slots, speaker names, waits/page breaks, and textbox text reveal over time when the referenced assets can be resolved. Portraits are composited from the base face plus eye/mouth pieces so normal animated portrait archives do not show transparent holes.
- **Build** — builds the map on one top-down canvas: a render of the terrain and props seen from above (redrawn about a second after a prop edit), the tile grid, the playable-area frame, the props (outlined over the tiles they cover) and the units of one deployment file (a disc coloured by army with the character's first letters; a dashed arrow leads to the tile the unit walks to after appearing). Layers can be shown or hidden (map image, terrain colours, heights - each tile shaded by its combined height, red highest - grid, props, script zones, units), and the units can be limited to one section. **Deployment file** picks which of the phase's `dispos.cmp` files is shown and edited: `dispos_n.bin` (Normal), `dispos_h.bin` (Hard), `dispos_m.bin` (Maniac) or `dispos_c.bin` (deployed on every difficulty). The status line shows the hovered tile's terrain and corner heights. Ctrl+wheel zooms, middle-drag pans. Tools:
  - **Select / move** — click a unit or a prop to edit it in the right panel, drag it to another tile; click any other tile to edit its heights. **R** turns the selected prop a quarter turn, **Delete** removes it; right-click offers the same, and **Tile heights...**.
  - **Paint terrain** — click or drag to paint a terrain type, or fill a rectangle; right-click picks a tile's type.
  - **Place prop** — click a tile to place the chosen prop at the chosen angle, at the ground height there. A moved prop keeps its height above the ground. **Add from another map...** lists the props of every other chapter map (the Map Objects browser, with its 3D preview); **Add to this map** (or a double-click) copies the chosen one in (its model, skeleton, animation, `texpack.tpl` images, flags and effect) and chooses it for Place prop. A prop of the same name that is the same model is just chosen; one that differs is copied under a name you give (suggested: `<name>_2`). The copy is undone like any other Build edit and written by **Save Chapter**.
  - **Tile heights** — click a tile to edit the four corner elevations (top left, top right, bottom left, bottom right) of each of its panel layers: **Combined** (what units and the cursor stand on), **Ground** (the land under objects) and **Roof** (buildings, on maps that have it). Values are the game's: -400 is one unit higher (a tile is 5 units wide), and two neighbouring corners 400 or more apart close the way between their tiles. Tiles share panel records, so an edited tile gets a record of its own and keeps its terrain type. **Deduce from terrain and props** estimates them: the ground is the terrain surface (or the deck of a low prop over it, such as a bridge), and the combined and roof layers are the ground, or flat at the height vanilla gives the props covering the tile (trees 7.19 units above their base, walls 4, houses about 6.3; a prop vanilla doesn't have rises to its model's top, unless its flags mark it as one that never does, like thickets). It reproduces about 80% of vanilla tiles, so check the result in game. Drag to select a rectangle of tiles: **Deduce** them all, or set every corner of one layer (or all) to one value. With **Heights follow props** (on by default) placing, moving, turning or deleting a prop deduces the tiles it covered and now covers.
  - **Place unit** — click a tile, choose the character, class and level; the unit is added to the chosen section of every ticked difficulty file, with the AI, army and flags of the section's first unit.
  - **Script zones** — the chapter script's map triggers: the zones a unit enters (`@on_area`, filled blue for the player side, orange for the enemy side, labelled with the function they run) and the tiles a unit acts on (`@on_location`, dashed purple, with the action: visit, door, chest, seize…). The **Script zones** layer shows them with any tool; hovering a tile lists them and right-click offers to select or delete one, or open its function in the Script tab. With the tool, drag a rectangle (an area) or click a tile (a location) to add a zone: it runs a new, empty function, or an existing function without a trigger chosen in **Runs** (the ones marked UNUSED first), which gets the zone's trigger. Click a zone to edit it in the right panel — its function's name and description, kind, side or action, tiles and event name — or drag it to move it; Shift+drag draws a new zone over an existing one. **Delete** (or **Delete zone**) removes a zone: an empty function (only `pass`, not exported, not called by another function) is deleted with it; any other function is kept without its trigger, and its description starts with `UNUSED: its map zone was deleted (was @on_…)`, so its code and old trigger can be reused. Zones edit the source open in the Script tab, so the Script tab shows them at once and **Save Chapter** compiles and saves the script too; the Script tab must show this chapter's script (not a shared one) and the script must parse.

  The unit panel edits the character, class, army (player, enemy, ally, partner), spawn and destination tiles, eight items (each with its **drop** and class-**ring** flags), five skills, the four AI entries, the laguz gauge, the AI turn order (lower acts first) and every deployment flag as a checkbox (autolevel, hold position, group commander, spawn if absent, blocked by bridge cover, and the unused bits 0x10/0x20/0x80). A **Section** block below edits the unit's section: its army name (Crimean Army, Bandits… from `FE8Data.bin`'s `GroupData`), whether units may be placed on occupied tiles, and the mode byte; **Apply to section** writes it to the same section in every difficulty when **Same edit on every difficulty** is on. Any character, class, item or skill of `FE8Data.bin` can be used, including ones the chapter never had. The difficulty table below it has a row per file (`c` is deployed on every difficulty; `n`/`h`/`m` are picked by difficulty): tick or untick a file to add the unit to it or remove it, and set its level and eight stat bonuses there. With **Same edit on every difficulty** (on by default) a move, a deletion and the form's other fields also apply to the same unit in the other files (same section, same character). A section only appears in game if the chapter script deploys it (see the Script tab).

  The **Map** buttons at the bottom left open four windows, which follow the chapter's edits:
  - **Objects...** — every placed object of the map (`mapbuildinst`, including the terrain and the scenery beyond the grid), searchable. Selecting one selects it on the canvas and the other way round. Its object, tile, angle (0°, 90°, 180°, 270° or a raw byte), height (the game's value; the model sits at -5 × height) and covered tiles are editable; **Apply** (or Enter) writes the changed ones. A move keeps the object's height above the ground and a turn recomputes the covered tiles; **Put on the ground** sets the height to the ground at its tile. **Add...** places an object, **Delete** removes one; **View model...** and **Export .glb...** show and save its model.
  - **Disposition...** — the deployment file shown on the canvas (its **Deployment file** picker switches both) with all its sections: name, unit count and army (link sections such as `<map>_date_<d>` are listed but hold no units). Selecting a section shows its header — army, occupied tiles, mode; **Apply header** writes it, to every difficulty with **Same edit on every difficulty** — and, under **Loaded by**, each chapter-script function that deploys it: every call with the section's name as a string argument (`Dispos("bmap02_first_n")`, `DisposSetMode(...)`…), or its name without the difficulty letter (the prefix the …Rank calls take), with its line. Click a function to open it in the Script tab. Below, a table of the section's units — character, class, level, army, spawn and destination tiles, the first four items, the AI entries, AI turn order and flags. Double-click a cell to edit it in place (Enter or leaving the cell applies, Escape cancels; flags open a checkbox list); **All fields...** edits any raw field and **Delete unit** removes the unit. Selecting a unit selects and outlines it on the canvas, and selecting one on the canvas selects its row. **Highlight the section's units on the map** (on by default) outlines the selected section's units in cyan on the canvas and fades the others, following the section you pick; **Show on map** scrolls the canvas to them. Edits are on the Build tab's Undo/Redo and follow **Same edit on every difficulty** like the unit panel (the level stays per file).
  - **3D view...** — the whole chapter in 3D (terrain and every placed prop), rebuilt a moment after each edit (**Update after each edit**), with the placement and gameplay grids.
  - **Map settings & chapter...** — capacity scale, light, fog, grid colour and the `mapextra` record (playable-area margin, map flags); **Import water .glb...** and **Water flow...**; and, under **Chapter (Game Data › Chapters)**, the same form as Game Data › Chapters for the record whose map is the open map folder (a **Record** list appears when several records use it, as trial maps do). It edits FE8Data.bin like Game Data does, so each edit shows in both places: fields apply when you leave them, and **Save FE8Data.bin** there (not Save Chapter) writes the file. **Open in Game Data ›** shows the record in Game Data.

  **Section**, beside **Deployment file**, limits the canvas to one section's units (or **All sections**) and picks the section **Place unit** adds to. **Add section...** adds an empty section (a name and its header: army, occupied tiles, mode); **Remove section** removes the picked one with its units, after asking. With **Same edit on every difficulty**, a section whose name ends in the file's difficulty letter (`_n`, `_h`, `_m`) is added to or removed from the other difficulties' files too, with their letter; the unit panel also edits the selected unit's section header (army name, occupied-tile placement, mode). **All fields...** in the unit panel lists the unit's 48 fields as stored, shown decoded (`0x4C (Group commander, …)`, `1 (Enemy)`, `1 (drop)`), unread ones included; double-clicking one opens the editor its kind needs (any label for the 4-byte fields, a checkbox per bit for the flags and item flags, a list for the army, a number for the rest) and changes that deployment file only.

  Edits go to the map, the deployment data and the Script tab's source, and **Save Chapter** (here, or in the Script tab for its part) writes them (keeping the extracted `map.cmp` and `dispos.cmp` in `originals/`); **Undo**/**Redo** (Ctrl+Z / Ctrl+Y, also in the windows) cover every Build edit and window edit, script zones included.
- **Script** — edits the chapter's event script as Python-style source ([Script language](script-language.md)): a **Function** drop-down to pick the function, a form for each function's name, export and trigger (type and parameters), a code editor with completion and error marks, an **Insert call…** picker for the game's functions, and a bytecode view. Saving compiles the whole script. The **File** box at the top right switches between the chapter's script and the shared ones: `startup.cmb` (the helpers every chapter calls and the campaign flags) and `ending.cmb`. A shared script stays open when another chapter is picked, and its unsaved edits aren't discarded by the switch; a link to one of the chapter's functions reopens the chapter's script. Compiling uses the project's own `startup.cmb`: its campaign flags and its exported helpers are known to every chapter script.
- **Battle scenes** — the phase's row of `BattleTerrData` in `FE8Data.bin`: the battle scenery (`zbg/<name>/`) drawn behind a fight, for each terrain type of the tile. The game finds the row by the map folder's name, so each phase has its own; an empty cell uses the default row's scene (row 0, shown after the cell), and a map without a row uses the default row entirely. Such a map shows the default row read-only, with **Give <map> its own row** and **Edit the default row** (every map without a row of its own uses it); a map with its own row has **Remove <map>'s row**. **Only terrain types on this map** (on by default) lists just the terrain types found on the map, with their tile counts. Each cell takes a scene name from the list or typed, and has **Browse…**: a window listing every battle scene (the `zbg/` folders, and names the table uses without a folder), with a filter and, for the selected scene, the maps already using it and a 3D preview rendered as it is selected (arrow keys step through them). **Use this scene** (Enter, double-click) sets the cell; **Use the default row's** empties it. Edits go to the shared `FE8Data.bin` like Game Data's; **Save FE8Data.bin** writes it.
- **Shops** (Path of Radiance) — the chapter's base shops in `shop/shopitem_<n|h|m>.bin`, one file per difficulty picked with **Difficulty** (Easy uses the Normal file). **Armory** and **Vendor** are ordered item lists with each item's icon (from `window/icon.tpl`) and price (cost × uses from `FE8Data.bin`, unsaved edits included). **Edit price…** (or double-click the item) changes the price; an item has one price for the whole game, not one per chapter, so the dialog warns that the change applies to every chapter's shops on every difficulty. It sets the item's cost per use in `FE8Data.bin`, rounding the price to a multiple of its uses. An item with 0 uses always costs 0 and can't be priced here. **Add** inserts the item picked or typed in the box below the selected one, **Remove** (or Delete) and ▲ ▼ edit the list. **Forge** is the fixed grid of 5 rows (swords, lances, axes, bows, tomes) by 9 bases (Iron, Slim, Steel, Silver, Thrown, Fire, Thunder, Wind, Light); each cell names the weapon offered or **(none)**. **Copy to other difficulties** replaces the chapter's three shops in the other two files. A chapter without shops (an added chapter) gets **Add shops for chapter NN**, a copy of the closest lower chapter's in every file. The files hold every chapter's shops, so edits stay when another chapter is opened; **Save Shops** writes the changed files, and `FE8Data.bin` too when it has unsaved edits (a price, or edits from other pages), keeping the extracted ones in `originals/`. Radiant Dawn's shop files use another layout and aren't editable.

## Global-data tools

- **Backgrounds and portraits** — view and replace supported textures.
- **Icons** — every generic icon sheet cut into its grid: items and menu glyphs (24×24), skills and statuses (32×32), the small 16×16 set, the card icons and, in Radiant Dawn, the debug event/terrain markers. Click an icon (or move with the arrow keys) to see it enlarged and, in Path of Radiance, the items or skills using it (Game Data's **Edit icon ›** opens this page on an item's or skill's icon); **Replace icon…** pastes a PNG over that one cell (stretched to fit), **Export icon…** / **Export whole sheet…** save PNGs, **Replace whole sheet…** imports a full sheet, **Restore original file** puts back the extracted sheet. The rest of the sheet decodes exactly as before, and the new icon's colours go into the sheet's spare palette entries (it is only reduced to fit when those run out). In Radiant Dawn, replacing an icon also updates the widescreen `icon_wide.cms` unless unticked. Path of Radiance's `system.cmp` copy of `window/icon.tpl` is refreshed at build.
- **Fonts** (Path of Radiance) — the five text fonts: system (menus), fe_font (the Tellius alphabet), talk (dialogue), bigkana (title and file menus) and alpha (staff roll), each with its glyph count, metrics, a preview line and its sheets. **Import TrueType/OpenType font…** renders a `.ttf`/`.otf`/`.ttc` into the selected font: size (Auto matches the game font's capital H), offsets, extra spacing and smooth or sharp edges, for every character the font has or only a typed list, plus characters to add; a before/after preview and a count of replaced, added and kept glyphs update as settings change. The game font's ascent and descent are kept so text stays on its lines, and glyphs the file lacks (kana and kanji, for a Latin font) keep their game bitmaps. Only characters with a Shift-JIS (CP932) code can be imported, since that is the game's text encoding. **Save** writes `Fonts/system.cms` (recompressed) or `Fonts/<name>.gcf` and keeps the extracted file in `originals/`; the build refreshes the `system.cmp` copies of fonts 1–4. **Export sheets as PNG…** and **Restore original file** are also there.
- **Illustrations, Ending Art, UI Windows, Misc Graphics, World Map, and Equipment** — view and replace the supported graphic resources exposed by `graphics_viewers.py`.
- **Music** — previews, exports, replaces, and adds supported music streams.
- **Videos** — previews, exports, replaces, and adds THP videos.
- **Game Data** (and each character page's **Stats** tab) — views and edits every table of `FE8Data.bin`: characters, classes, items, skills, terrain, chapters, battle scenes (on each chapter page), difficulty constants, army groups, battle skies and supports.
  - **Adding and removing records**: Classes, Items and Chapters have **New…** and **Remove** next to the picker (characters have them on their page and on the Characters list). **New…** asks for the ID (`JID_`, `IID_`, `PID_`; a new chapter gets the lowest free chapter id) and a record to copy, or an empty one, and appends it at the end of the table. **Remove** is refused while anything still names the record by its ID — other records, support lists and bonds, skill restrictions, chapter scripts, deployments, shops, the model tables and `main.dol` itself — and lists what does. Saves hold characters, classes and items by their number in the table, so removing one renumbers the ones after it and saves made before the change load other records (the confirmation says so). Skills and terrain types keep their count: the game refers to skills by their position and walks exactly 77 terrain types. A new record is unsaved like any other edit; a new character appears in the Characters list once `FE8Data.bin` is saved.
  - **Classes**: ID (`JID`), name key (`MJID`), description key, promotes-to (**Open ›** goes to that class), **AID (class model)** (the animation ID used by units whose character has none), **innate weapon** (the transformed laguz's attack), weapon ranks (one drop-down per weapon type: `-` unusable, `*` no fixed rank, or a letter; a rank string no class uses yet is added to the file, so classes that shared the old one keep it), the five innate skills, movement, build, weight, **skill capacity**, **vision** (fog-of-war sight), **movement type** (which terrain cost column the class uses), caps, base stats (`0x44`), growth rates (`0x54`), **growth modifiers** (signed, `0x5C`) and the **categories** (check boxes, up to 3: what weapons are effective against).
  - **Items**: category toggles above the tiles (All, Sword, Lance, Axe, Bow, Knife, Fire, Thunder, Wind, Light, Staff, Laguz strike, Item, Accessory) limit the tiles and ◀ ▶ to that kind of item; a search covers every category. Every field of the record, decoded — there is no hex box. Item ID (a new ID is added to the file; one another item has is refused), name and description keys, weapon type, attack type (Fire/Thunder/Wind/Light hit with Mag against Res), rank needed, weapon EXP per use, icon (shown next to its number; **Edit icon ›** opens it in Assets › Icons; items sharing it are listed), might, hit, crit, weight, uses, minimum and maximum range (255 = Mag/2), cost per use (shop price = cost × uses), the **properties** (check boxes, up to 6: brave, unbreakable, poison, personal locks…), **effective against** (check boxes, up to 2), use and weapon effects, attack trail colour, and the stat and growth bonuses while equipped (signed). Type, rank and property words missing from the file are added to it.
  - Weapons (swords, lances, axes, bows, knives, and any item whose table names a model) show their **battle model**: the battle looks the item ID without `IID_` up in `zdbx.cmp` (`xwp/<NAME>.dbx`), whose `Model` block names the folder and model (`xwp/ironsword/ironsword.cmp`). **Open 3D model ›** opens it in 3D Models, **Forged model ›** the forged version (`xwp/forge/<name>_b`). An item with no table gets no weapon in battle (in vanilla, the Devil Axe and the ballistae); a new item ID needs its own table.
  - **Skills**: ID (`SID`; the record's own symbol is renamed with it), Japanese name, menu name key (`MSID`), both help keys, effect (`EID_`), description, the **restriction list** (the `PID_`/`JID_` labels the skill is exclusive to, separated by commas; empty: anyone), the scroll that teaches it, the **icon** (its number, the picture and **Edit icon ›**; 0 means none, and the skill is then left out of the lists a unit can learn from), the **capacity cost** (skill capacity it uses) and a byte that is 1 on the skills taught by a scroll (the game never reads it).
  - Classes, skills, chapters and characters also show the **whole record as hex**, editable except its pointer words (listed above the box; the loader relocates them, so they are changed through their own fields). The undecoded bytes (class flag bytes…) are changed there.
  - **Terrain**: a terrain type's name (map tiles name their terrain by it, so renaming it needs the maps renamed too), display-name key, avoid/defence/resistance (and the flag-4 variants), heal % per turn, object-tile flag and movement cost per movement type. A type sharing its stats block with others changes them all (the page names them); **Give this type its own stats** copies the block for this type alone.
  - **Chapters**: every field of a `ChapterData` record — title key, chapter id (what scripts change chapters by; 90 and up are the trial maps), map, script, message file, map music, the four objective texts and their Hard and Maniac overrides, base and conversation backgrounds, class-change scene map and sky, enemy bonus levels per difficulty, the trial maps' grade thresholds (turns, units lost, kills) and the record as hex. The record of a chapter's map can also be edited from that chapter's Build tab (**Map settings & chapter...**).
  - **General**: the difficulty constants (`GameData`: battle EXP bonuses, boss and thief kill EXP, promoted-unit EXP base, laguz growth bonus and the class critical bonus, one byte per difficulty), the army groups (one `MG_` key per line, group numbers and English names beside them; deployments name groups by number, so new ones go at the end), the battle skies (one sky per map weather id) and the file's build time and author.
  - **Map Objects** lists every prop of every chapter map (`zmap/<map>/map.cmp`, read in the background the first time the tab opens; **Rescan** rereads maps saved since): map, object name, how many times the map places it, the tiles it covers, its height in tiles and its kind (static, animated, effect). Search narrows by name, **Map** to one map, and **One row per name** hides the other maps' copies of a name. Selecting a prop shows it in 3D (animated props play their animation); **Export .glb...** saves it. It lists the saved maps: unsaved Build or Map edits appear after **Save Chapter**. To use a prop on another map, use **Add from another map...** in that chapter's Build tab.
  - **Supports** has three tabs. **Pairs** lists every support pair (thresholds, bonus at A, which conversations exist) with the problems across all lists (one-sided pairs, falling thresholds); double-clicking a pair opens the character page's **Supports** tab, where a character's affinity, partners and bonds are edited. **Affinity bonuses** is the bonus table per rank. **Conversations** is a Dialogue editor on `yell.m` (Message ID box, step list, Step and Raw text tabs, preview) with its own **Save**.

  Saving keeps the extracted `FE8Data.bin` in `originals/`. The build and the patch copy it into `system.cmp`, whose copy is the one the game reads. Leaving the page, building, making a patch or closing the project first applies the field that still has the focus.
- **3D Models** — views supported models, skeletons, and animations: map models (`ymu/<class>`), battle models (`zu/<code>`, all weapon packs of the folder as one set), battle scenery (`zbg/`) and weapons (`xwp/<name>`, and `xwp/forge/<name>_b` for forged weapons; Game Data's items link here). Shapes the game never draws (flag `0x400`, such as the weapon placeholders inside battle models) are left out of the preview and the export. **Export .glb...** saves the selected set (mesh, skeleton, textures, animations) for Blender and other glTF tools. **Import .glb...** replaces the set's mesh and repacks the `.cmp`; the skeleton and animations are kept. On battle scenery (`zbg/`) and weapons (`xwp/`) the model is imported as unskinned geometry and the set's `.tpl` is replaced when the model has textures; a weapon keeps its skeleton and moves with its first bone, and bows are refused (their string bends through skinned shapes this import doesn't write). A material's glTF alpha mode (Blender's blend mode) sets how the game draws it: opaque, alpha clip (`MASK`, for cut-outs such as leaves; pixels under half alpha are dropped) or alpha blend (`BLEND`, translucent). Exported sets carry the mode each material has in the game, so keep it when editing. On a map model (`ymu/`) or a battle model (`zu/`) the model must be weighted to the set's armature (export the set first and weight to its bones). Vertices weighted to several bones (up to four) blend smoothly, as in the game's own battle models. A battle model is written into every weapon pack of its folder and built entirely from CPU-blended shapes, the only kind that draws correctly in battle. Its textures stay as they are when the glTF images come from one of the folder's `.tpl` files; new images replace every `.tpl` of the folder (256×256), so every unit using that battle model shows them. Do not model weapons into a battle body: the game draws the equipped weapon's own model, and a modelled weapon would appear next to it. On a map model, a texture identical to one of the class's `tex_N.tpl` variants keeps them all; a new texture is fitted to 128×128 and written to every variant, so all units of the class share it. **Import animation...** (map and battle models; a battle animation is rewritten in the weapon pack that holds it) replaces one of the set's animations with an animation from a glTF file; the replaced animation's events (hit frame, sounds) are kept unless the glTF carries its own. It warns when the new animation moves smoothly weighted vertices beyond the range the body stores; re-importing the body afterwards resizes it. **Replace rig...** builds a new skeleton from a glTF armature and rebuilds the body and **every** animation on it; the armature must keep the old rig's underscore-named anchor bones (`_s1_`, `_sw1_`, `_r_hand_`...). On a map model (`ymu/`) the glTF must contain an animation named like each of the class's animation files. On a battle model (`zu/`) every weapon pack is rewritten: an animation the glTF has under a file's name (`fig1_at1_ax`) is imported, every other one is moved from the old skeleton by bone name (tracks of bones the new rig lacks are dropped, positions follow the new proportions), and the review lists both counts. When fewer than half the old body bones are in the armature (a new skeleton with its own bone names), nothing can be moved by name, so the glTF must provide every animation: a missing follow-up clip (`fig1_cr1_ax_at1`) reuses its base clip (`fig1_cr1_ax`), a clip missing for one weapon reuses the same role of another (`fig1_dam_no` from `fig1_dam_ax`), `name@pack` (`fig1_dam_ax@ha`) fills one weapon pack only, and anything still missing refuses the import. Both rig imports refuse an animation that lacks an event code the fight waits for (`0` the blow lands and `1` the swing on melee attacks, `2` the release on throws) where the original has it; an animation without events of its own keeps the original's, retimed. A map rig is also checked for its weapons: each animation must show and hide the weapon bones (`Ax`, `Ax1` on the Fighter) as the original does, by scaling them to 1 or 0. **Rig kit...** writes what a replacement rig must provide: a `.glb` with the set's skeleton, body and every animation named as **Replace rig...** looks for them, a `.md` checklist (the anchor bones with their positions and purpose, the map weapons each animation shows, and every animation with its pack, frame count, loop, role from `zu/<code>.dbx` and events, the required codes in bold) and a `.json` of the animation list for scripts. **Fit new rig...** puts any rigged humanoid glTF (one texture) on a map or battle model with **its own skeleton**: it finds the feet, hands, head, pelvis and chest on both skeletons (from the game rig's anchor bones, else from the shape of the body), guesses which game bone each model joint follows, and shows that mapping for editing (blank: the joint follows its parent, for fingers or hair; **Save mapping...**/**Load mapping...** keep it as JSON). The model is then scaled to the game model's height and turned so each bone points like the game bone it follows; the game's anchor bones are added under the matching joints (on a battle model, on small carrier bones at the game offset) and, on a map model, the weapon bones with the game's own weapon meshes. Every animation of the set is retargeted: each joint turns as its game bone turns, the pelvis moves as the game's does, weapons are shown and hidden as before, and the events are the game's. The result goes through **Replace rig...** (and its review); the fitted glTF, with its skeleton and every animation, is also saved next to the chosen model as `<model>_on_<set>.glb`, for editing in Blender. A mesh weapon held by the model can be taken for its hand: check the arm lines of the mapping. On a map model (`ymu/`), **Import .glb...**, **Replace rig...** and **Fit new rig...** offer to reduce a model with more triangles than any vanilla map model (853; the median is 444). You choose the triangle count (suggested: the current body's, or 500). The reduced copy keeps the texture layout, the skin and the map weapon meshes, and is saved next to the model as `<model>_<count>tris.glb` (for **Fit new rig...**, inside the saved fitted model). **Keep all** imports the full mesh. **Events...** edits an animation's event track: pick the animation, then add, change or delete keys (a frame and one to four codes); it warns when a code the fight waits for is removed. Battle imports also warn when visible vertices are bound to bones the original body keeps free (the weapon, camera, foot and root sockets): the game attaches the real weapon to the hand, so a weapon modelled into the body is drawn next to it. The animation preview poses the model exactly as the game does.
  - The 3D previews (models, chapter maps with their props) are drawn on the GPU when the optional `wgpu` package is installed, fast enough to orbit and zoom a full chapter smoothly (a chapter scene loads in about a second); without it they use a much slower CPU renderer. Drag to orbit; the scroll wheel zooms toward the cursor (up to 300 times the fitted view); right-drag, middle-drag or Shift+drag pans; **Reset View** and **Top Down** re-centre it.
  - Every import opens a review window before writing anything. It shows the converted set in the preview (an imported animation is selected and posed), the figures of each changed file next to the current ones, the glTF joint → game bone mapping, and the warnings. The figures are triangles, vertices, blended vertices, shapes, bones, frames, keys, events and file size, plus the stored precision and range. Figures above the largest vanilla model of the same kind (map or battle model) are shown in red; the game has handled models that size, and nothing larger has been tested. **Write files** writes and repacks; **Cancel** leaves everything as it is.
  - The first time an import overwrites a file, the file as extracted is copied to the project's `originals/` folder. **Restore original...** puts every kept file of the selected set's folder back.
  - Chapter maps are listed as `zmap/<map>`; the preview shows the terrain with every prop in place. **Export .glb...** writes the land terrain alone (props and water left out), in the game's coordinates (5 units per tile), with each material's first texture. **Import .glb...** replaces it with a static mesh; it first asks whether to move the tile heights and props with the new ground and whether to fit the playable area to the tile grid (both on by default). Its images are added to the map's `texpack.tpl` (up to 1024 pixels a side), and images no model uses any more, such as the replaced ground's, are removed. By default a material named `map_base`, `map_wall` or `map_water` is renamed, and the terrain shows its own texture only. With **Keep map texturing** (on when the glTF has a `map_base` material, as every exported terrain does) a `map_base`/`map_wall` material keeps the game's road and shore texturing: its texture is the atlas, sampled through the glTF's two UV sets (`TEXCOORD_0` and `TEXCOORD_1`), and a grey mask picks between them (white shows the second UV set: roads, shores). **Export .glb...** writes the current mask next to the glb as `<name>_mask.png`: 640 × 640 units (128 tiles, 4 pixels per tile) from the terrain's corner, x to the right and z downwards. Paint it and choose it as the mask image, or leave the mask empty to keep the current one. White shows the atlas through the second UV set, whatever that UV set points at there: to add a road, paint the mask white and point the second UV set at the road part of the atlas in your 3D editor. **Keep the map's light overlay** keeps the vanilla light and shadow image (made for the old ground); off, it is white. Units stand on the tile heights stored in `map.bin`, not on the mesh, so the import moves those heights (and every prop) with the new ground, and the review says how many tiles and props moved and how many passages between tiles the new slopes block (the game closes an edge whose corners differ by one unit or more). The move grid is drawn from those heights as one flat panel per tile half, so the import also cuts the playable area of the mesh along the tile lines and diagonals and flattens it onto the panels; detail smaller than a tile is lost there. Images the replaced terrain alone used are dropped from `texpack.tpl`, so repeated imports don't grow it.
  - **New slot...** (map and battle models) copies the selected model so one character or class can get its own model while the vanilla one keeps serving everyone else. For a battle model (`zu/`) give a new 4-character code (lowercase letters or digits) and the class, plus a character to limit it to that character; the copy is a new `zu/<code>/` folder with its own tables in `zdbx.cmp`. For a map model (`ymu/`) pick the animation ID to copy (for example `AID_FIGHTER_BO`, Boyd's), a new ID (`AID_` and capitals) and a new folder (empty shares the source folder), and optionally the character that uses it (unpromoted or promoted). Then import into the copy as usual. The Prologue's Boyd is `PID_BOLE_MAP1`, a separate character from `PID_BOLE`. **Model tables...** opens the tables that pick every unit's models:
    - **Battle job list**: every line (class, class plus character, or animation ID → model code), **Set line** and **Remove line**, and a check showing which battle and map model a character gets (unpromoted or promoted).
    - **Battle textures**: a battle model's texture lines (army keys `自軍` player, `敵軍` enemy, `中立` other, `味方` ally, a character or an animation ID → a `.tpl` of the folder), **Set** and **Remove**; **Remove this slot...** deletes a model made with New slot... (its folder, tables and job-list lines; a line the game's own list had gets its original model back).
    - **Map models**: an animation ID's records (folder, texture number per army, blend weight, animations), **Set textures**, and **Remove this slot...** (its records, its copied folder, and characters or classes pointing at it back to their extracted IDs).
    - The game's own models cannot be removed.

The Build tab's **Import prop .glb...** (Place prop tool) imports a glTF as a prop: a new name adds an object, an existing name replaces that object's model; the Objects window's **Export .glb...** exports one. Imports remove the `texpack.tpl` images no model uses any more (a replaced model's) and renumber the other models' textures to match. Model a prop at 5 units per tile with the tile's corner at the origin; it turns around the tile centre. A prop does not block movement by itself: paint its tiles' terrain type (for example Obstacle) for that. Exported models keep, in each material's glTF `extras`, what glTF cannot express (additive or subtractive blending, the material's second and third colours), and imports restore it: glowing flames and similar effects survive a round trip. A glTF with an armature and an animation becomes an **animated prop**: its own skeleton, the mesh weighted to it and the first animation, looping or played once (the import asks); **Export .glb...** on an animated prop includes its skeleton and animation, and a static model imported over an animated prop removes them.

**Import water .glb...** (Objects tab) replaces the map's water surface (the selected water object, else the first). Model it in the terrain's coordinates (export the water with **Export .glb...** to start from it; vanilla water is a flat plane at y = -2). It keeps the water material, its colours, its scrolling animation and its textures; an image in the glTF replaces the first texture. On a map without water it asks which map to copy the water animation and textures from, adds `<map>_water0` and sets the map's water flag. **Water flow...** edits the selected (or first) water object's scroll speeds: four numbers, `u` and `v` for each of its two textures (the Prologue's are −0.124 0.36 −0.231 −0.572; negative runs the other way). The map flag word itself is `unknown_tail` among the Extra fields (bit `0x20` water, `0x10000000` roof and house tiles). An object's flag bytes and an instance's covered-tiles rectangle (`x2`..`end_y2`) are editable in the Objects and Instances tabs; the rectangle matters only for roofs, houses, doors and rocks (flag byte c bit 3 or 4). The import reports tiles under the water that are not a water terrain type, and water-type tiles left dry; paint them with the Build tab's **Paint terrain** tool.

Terrain types are painted with the Build tab's **Paint terrain** tool: the list shows each type's English name, Japanese name, and its avoid/defence/resistance, healing, or "impassable"; hovering a tile shows its type. The yellow frame is the playable area. A type such as Fort (`砦`) is an impassable building in this game; the healing tile is Heal (`回復`). **Save Chapter** keeps the extracted `map.cmp` in `originals/`, so **Restore original...** in the 3D Models panel (`zmap/<map>`) undoes map edits.

Pages link related records: a deployment unit's **View Stats...** and every cast card open the character page, which links to its class, portrait, models, chapters, messages and script functions.

## Scope limitations

The feature set reflects the formats currently understood by the project. A visible record or raw field is not necessarily editable. New labels, shared data, executable-controlled behavior, and incompletely understood fields may remain read-only to avoid unsafe changes.

The FE9 dialogue preview uses real face-table coordinates, portrait depth, window descriptors and game glyph metrics. Auto-advance defaults on; selecting another message resets to its first frame, and playback highlights its current source position in the editor. Unambiguous inherited scene context is recovered from direct chapter TalkEvent branches. The editable **Inherit from message** field shows the detected predecessor: choose a chapter message or type its ID and press Enter/Apply to use its final scene as the preview's initial context. Clear it to remove inheritance; **Auto** restores script-derived context. These overrides affect only the preview and reset when selecting another message. The expandable context panel also supports individual property adjustments. It renders the selected message, not the 3D map/event VM. Animation timing, some formatting and nonstandard descriptors still have limits documented in [Conversation rendering](https://klg-tellius.github.io/TelliusModding/tellius_archive.html#/message-format). FE10 retains its earlier, unvalidated preview.

### FE9 scene editor

The step list shows the selected message as steps: layout, background, transition duration and fades; portrait load/remove, eyes, blink speed, mouth set and seat selection; box speaker, select, dismiss, window visibility and nameplate; lines of text; wait for input; yield to script; and the recognised but undecoded controls (`$UB`, `$Ub`, `$SD`, `$SE`, `$G`, `$Y`, `$C`, `$O<n>`). Anything else becomes a Raw step that keeps its bytes. Every vanilla message decompiles without Raw steps, and untouched steps keep their exact source.

- The pinned **Starting scene** row shows what the message inherits: the preview's resolved or overridden initial context.
- **Add step** inserts after the selection. Steps can be duplicated, deleted and moved (also Delete and Alt+Up/Down in the list). Selecting a step moves the preview to the scene after it, and playback highlights the playing step.
- The step form edits the selected step's fields. Portraits and backgrounds have searchable pickers with previews. A Line has a speaker target (`$F<n>`, `$s<n>` or `$W<n>`), "clear box first" (`$P`), "wait for input" (`$K`), and a text box where inline commands (`$w<n>`, `$MC…$MD`, `$N`, `#C`, `#F`, …) are highlighted and described on hover. An **Insert** menu adds common ones. A **Font** menu draws the selected text in another font: the Tellius alphabet of the ancient-language lines (`#F01$O2…#F02$O1`, which also switches the typing sound as vanilla does), system, bigkana or alpha (`#F00`/`#F03`/`#F04` … `#F02`). A font switch lasts one textbox line, so each selected line gets its own codes; with nothing selected the pair is inserted at the cursor, and **Remove font codes** strips them. The preview warns when the text uses a character the chosen font lacks (the game draws ☆, or a space in the fonts without one).
- The **stage** shows every seat of the current layout after the selected step, with the speaker highlighted. Click an empty seat to load a portrait. Right-click a portrait to replace or remove it, make it speak, or change its eyes, blinking or mouth set. Layouts with at most five seats (上下会話, 背景上下会話, TUT会話, ダイアログ会話) use box commands (`$c`/`$d`/`$s`); larger ones use seat commands (`$F`).

Message IDs are listed and saved in ascending byte order, like every vanilla file. The game itself looks IDs up through a hash, so order does not matter to it. A new, duplicated or renamed ID is rejected if it already exists in the chapter or `common.m`, or if it shares the engine hash key with one of those IDs. Renaming or deleting warns when the chapter script (`.cmb` or its `.fe9s` source) still references the ID; scripts are never edited automatically.
