# FE8Data.bin: how the game refers to its records

Summary for the documentation (full table in `research/FE8DATA_NOTES.md` §4.7, "Table limits").

- **Every section is found by name.** At boot the game looks each section up through the file's symbol table (`PersonData`, `JobData`…), so the position of a section in the file does not matter.
- **Characters, classes and items are sized by their count word.** The loader reads the count, allocates that many runtime records and numbers them from 1 (character `+0x18`, class `+0x38`, item `+0x0E` in memory). A table with more records works without any change to the executable.
- **Saves hold these three kinds by number.** A saved unit stores its character and class as 1-based table numbers (u16), and each of its eight item slots stores the item number (u16) and a second u16. The support-conversation state also keeps two character numbers. Inside the running game, units point at their records directly and records name each other by ID (`PID_`, `JID_`, `IID_`), never by number. So appending a record keeps every save valid, while removing or reordering records makes older saves load a different character, class or item.
- **Skills are bound to their position.** Skills live in a 128-bit mask per unit and are checked by their table index: about 466 calls in the executable name a skill by a literal index (Crit+ is skill `0x61`). The loops that read skills by name, list learnable skills and draw the skill-capacity screens all stop at a fixed 98, the vanilla count. The skill table can be edited in place, but a 99th skill would never be granted or shown, and moving a skill would give its behaviour to another.
- **Other fixed counts.** Terrain types: exactly 77 (the terrain-name table is built over a fixed 77, and map tiles name their terrain by its Japanese name). Affinities: fixed by the executable's own list of names. `GameData`: seven rows, one byte per difficulty, no count.
- **Tables that can grow freely.** Chapters (found by their chapter id byte, so up to 256), army groups (dispos name a group by number: new ones go at the end), battle skies (one per weather id, a count byte), battle-scene rows (found by map name, any order), support lists and bonds (named by PID).
